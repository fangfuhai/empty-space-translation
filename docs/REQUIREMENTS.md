# 需求与验收记录

本文整理本轮及此前用户提出的产品要求、使用反馈和开发边界。内容为需求摘要，不包含私人聊天或完整个人配置。以 1.0.13 / FIX8 源码和已记录验证为准，区分实际实现与仍需验证的问题。

## 产品目标

可靠、轻量的 Windows 后台输入翻译工具，调用本地 Ollama。优先可靠性、原意和连贯性，其次优化速度；模型、算力和硬件可以评估，但不能盲目增加模型体积与内存占用。当前用户对 FIX8 使用效果满意。

## 交互和任务生命周期

- 双空格获取当前输入框全文，含中文时译成英文；提供选区译英文/中文和暂停快捷键。
- 捕获完成后，切窗或继续输入只取消自动替换资格，模型请求继续；完成后交付剪贴板。
- 同一输入框且未编辑时，粘贴前重新核对原文，符合条件才自动替换。
- 不自动发送消息，不积累聊天历史，不执行待译文字中的命令。
- 暂停、退出、超时、取消和异常需正确释放任务状态、锁、请求与剪贴板资源；不得通过吞异常或回拨输入活动计数掩盖错误。
- 剪贴板无需事先放入文字；捕获/交付失败应明确提示，失败交付的译文可重试复制。

## 历史反馈与当前处理

| 反馈 | 当前处理与证据边界 |
| --- | --- |
| 使用一定次数后无法翻译，怀疑上下文累积 | 每次请求仅系统消息和当前输入；顺序请求、取消后恢复、资源释放有测试。历史故障根因未被证明，未加定时重启。 |
| 情绪不清楚、不应增强承诺或软化拒绝 | Prompt 要求保留原意、拒绝强度、不确定性和承诺；具体语义仍需人工评估。 |
| 日期保留中文年/月/日 | 中文日期整体保护并转为英文日期；支持中文数字、缺省日后缀和闰年验证。 |
| 长句遗漏“接下来测试……”句首 | 对符合规则的短冒号前缀和正文分别要求非空输出；共同上下文、同次请求，缺失则校验重试。 |
| 偶发空译文 | 空输出、无效 JSON、缺失字段、截断和损坏保护信息拒绝交付。 |
| 常用短语希望节省模型请求 | 少量整句精确匹配；不做模糊或子串替换，不缓存私人聊天。 |
| 疑似需要剪贴板预先有文字 | 空剪贴板捕获和恢复有模拟测试，无此产品前置要求。 |
| 中英混合句、现货、放心、拆开等词语残留 | 英文方向要求译完中文片段并检查残留；短句避免泛化拒绝。历史记录中的句子可能是输入，也可能是输出，不能统一归因。 |
| “二〇二六年九月二十九日”“十月二十七”“9月10” | 定向日期解析；单独中文日期本地转换，不调用模型。 |
| 八百八十八人民币、778 美元等金额 | 中文数字金额作为整体保护，不拆金额币种、不计算汇率。 |
| “明天，你可以放心”“你可以放心” | 整句匹配；没有到货承诺就不补承诺。否定/附加条件的长句不走短语匹配。 |
| “那我就拭目以待吧” | 整句匹配为 “I'll just wait and see then.”，不增加 “That's great”。 |
| Please ship on 2028-02-29, do not ship early. | ISO 日期整体保护，提示不泄露日期值，保留“不要提前发货”；本机验证成功。 |

## 必须保留的开发约束

1. 先读当前源码、生效配置、AGENTS.md（如有）和 Git 状态；旧报告不能替代事实。运行 EXE 与源码不能证明一致时必须说明。
2. 保留已有用户改动，不 reset、不覆盖无关修改、不擅自清理；本次目录清理由用户另行授权。
3. 金额词识别不能把“模块”“单元”“一块蛋糕”解释为人民币，也不能拆成“100、CNY”。
4. ProtectedText 静态初始化崩溃属于失败，不能算 SKIP，不能无证据归因于沙箱。
5. 校验不能只靠长度、哈希、JSON 或数字存在证明语义；不得关闭保护、吞异常或修改输入活动序号让测试通过。
6. 审查完整链路：触发 → 捕获 → 文本保护 → 模型请求 → 解析清洗 → 恢复 → 校验 → 替换/剪贴板。
7. 运行测试前理解副作用，明确 PASS / FAIL / SKIP；真实桌面和模型测试与无桌面测试区分。
8. 不上传密钥、完整个人配置、诊断导出或私人聊天。可以向用户索取最小复现和人工测试反馈。
9. 最初接手阶段仅审查，后续用户明确授权修复、构建、目录清理和公开 GitHub 资料；这些是分阶段授权，不应把最初限制误当永久禁止。

## 验收重点

检查金额币种、日期、主客体、情绪、否定、承诺和句首完整性；分别测试同框未编辑、继续输入、切窗、暂停/取消、空剪贴板及交付失败重试。用户已完成此前提供的实际使用测试并认可 FIX8，但不能据此声称任何输入都完美。

未来优化优先保持可靠性和当前体验，可少量扩充整句词库并测量延迟；更换模型、扩容或提高并发应有资源测量依据。
