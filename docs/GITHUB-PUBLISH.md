## 产品介绍

**空格翻译 SpaceTranslate** 是一个面向日常聊天、商务沟通和行业交流的 Windows 后台翻译工具，由 **linthon（方赋海）** 设计与维护。

它希望减少在输入框和翻译网页之间反复切换的操作：写完文字，快速按两次空格即可翻译。译文完成后，若仍停留在原输入框且内容未编辑，符合条件时会原位替换；若已经切窗或继续输入，翻译继续，结果交付剪贴板供手动粘贴。软件不会自动发送消息。

翻译通过本机 Ollama 运行，准备好本地模型后可离线使用，无需云翻译 API 密钥。客户端采用 C# / .NET 8 WinForms；实际速度和资源占用主要受所选模型、输入长度和硬件影响。

视觉标识是一枚海蓝色空格键：空格代表主要操作，“海”呼应作者姓名。正常托盘图标为蓝色，暂停状态为灰色并带暂停标记。

## 两个版本如何选择

| 项目 | 1.0.15 稳定版 | 1.1.0 Preview 试用版 |
| --- | --- | --- |
| 适用需求 | 日常中英翻译 | 体验词库、多语种和日志导出 |
| 双空格 | 含中文的输入框全文译成英文 | 全文译成所选目标语言，不再要求包含中文 |
| 中英快捷键 | 支持 | 保持相同快捷键 |
| 自定义 TXT 词库 | 不支持导入；有少量内置短语 | 支持导入，指定译法优先 |
| 新增七种目标语言 | 无 | 法、土、泰、日、俄、西、韩，试用 |
| 原位替换 | 条件满足时执行 | 中英保持；新增语言仅交付剪贴板 |
| 故障日志导出按钮 | 无 | 支持，默认不含聊天内容 |

首次使用建议选择稳定版。试用版新增语言尚未通过完整语言质量验收，土耳其语和韩语实测出现过语义或混合语言问题，因此不能宣称“九种语言均已稳定支持”。

## 项目坚持的要求

- 可靠性优先：保留原文，任务失败、取消和异常后正确释放资源，不依赖定时重启掩盖问题。
- 不积累聊天上下文，每次翻译使用当前输入；不回答或执行待译文字中的指令。
- 保留情绪、拒绝强度、不确定性、疑问和承诺，不擅自添加保证或商业承诺。
- 保护金额、币种、数字、日期和型号；不计算汇率，不把“模块”“单元”“一块蛋糕”等误当金额。
- 保留句首和正文，拒绝空译文、缺失或损坏的保护信息；格式有效不代表语义完整。
- 继续输入或切窗后不覆盖新的内容；剪贴板无需事先有文字；不自动发送消息。
- 常用短语按整句精确匹配；行业术语由用户按目标语言指定，不以模糊替换改变长句含义。
- 优化速度时关注内存，不自动下载更大的模型或盲目增加并发。
- 日志和问题反馈尽量不包含私人聊天、完整配置、词库正文或密钥。

完整历史反馈与验收边界见 [需求记录](REQUIREMENTS.md)。

## 发布内容安排

仓库首页使用根目录 [README](../README.md)。两份可直接复制的 Release 正文：

- [1.0.15 稳定版发布说明](RELEASE-1.0.15.md)
- [1.1.0 Preview 发布说明](RELEASE-1.1.0-preview.md)

发布包建议命名为 `SpaceTranslate-1.0.15-win-x64.zip` 和 `SpaceTranslate-1.1.0-preview-win-x64.zip`。将对应目录中的四个运行文件一起打包，附上对应发布说明及许可证；不能只上传 EXE。本次两个包都依赖已安装的 .NET 8 Windows Desktop Runtime x64，不是自包含单文件版。模型和 Ollama 需单独准备。

**源码版本务必分清：当前 `source/` 已是 1.1.0 试用版，不能标成 1.0.15 源码。** 1.0.15 的现有运行文件已保留，但若没有单独验证的历史源码快照，应明确说明该版本发布的是保留的二进制包。不要把当前源码打一个 1.0.15 标签就称为可复现的稳定版源码。GitHub 自动生成的 Source code 附件也取决于所选标签的实际内容。

试用版发布时勾选 **Pre-release**。源码、必要文档、Logo 和许可证可以纳入仓库；发布运行文件放入 Release 附件。个人配置、日志、私人词库、编译缓存、旧导出包不上传。

两份发布说明随源码上传；现有两个运行包通过仓库 downloads 目录提供下载，不依赖 GitHub Release 页面。
